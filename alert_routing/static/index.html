07 ABOUT / SCALE-OUT — what is NOT in the core, and why (deliberate)

The routing core is deliberately small and provable. These are the documented next steps, each post-decision — they never feed back into who is notified. The routing path stays deterministic.

  • AI chat on the incident — a console assistant that can only explain/query the decision log, ledger, and timeline. Read-only, injected from the entry point (same seam as the "why you" prose). Worth building as the product's interface layer — not as the router.
  • Kafka in front — buffering + replay for bursty ingress and per-alert_id ordering (partition key), durable commits so a crashed router can be restarted without dropping or double-sending (dedup is already physical, so replay is safe). Overkill at this scale; the seam it would fill is Presence.subscribe().
  • Runbook RAG — retrieval that enriches the post-incident summary, never the routing decision.
